Audit date: 2026-10-28
Baseline: before fixes in the current task. Source audit was completed manually.

System save path (baseline)
---------------------------
NewConsultationForm first validates the optional medicine panel, reads the
registered patient in FormPopup.SaveController.prepareAsync, then calls
`verifyStock` and one `ClinicSystem.recordVisitAndAdminister(...)` call in
saveAsync. `SecuredClinicSystem` authorizes the visit and, when medicine rows are
present, DISPENSE permission; it calls the `ClinicData` campus-aware combined
operation. The in-memory implementation checks all requested items and aggregate
quantities before adding the visit and dispensing rows. The persistent repository
runs the operation inside one Database transaction and saves the aggregate only
when it completes. A database exception rolls back the unit. The service method
currently accepts only a boolean allergy confirmation; it cannot preserve a
written override reason. A separate sequence of `recordVisit` then
`dispenseMedicine` calls would lose that atomic boundary and visit linkage, so
that route is not acceptable.

Post-fix verification
---------------------
The checks below ran after the consultation, stock and allergy fixes. No
ClinicSystem signature, role or permission was changed.

- MedicinePicker results are bounded to 25, include earliest expiry, and show
  expired-only/zero-usable-stock medicines as disabled “Out of stock” results.
  Selected text renders the full medicine name instead of the Java object value.
- The medicine field, ATC field, quantity, stock label and full Remove label fit
  at the normal 1000x700 layout and at the tested compact 312x300 layout.
- An unselected/empty row shows “Choose a medicine or remove this row.” under the
  row, keeps its search text, scrolls that message into view and focuses the
  medicine field. Quantity above usable stock reports “Only N left in stock”.
- Each selected medicine gets an asynchronous allergy status. Patient allergies
  are shown once above the rows. The existing AllergyConfirmPopup now requires a
  written override reason; cancellation saves nothing, and confirmation retains
  the reason on the dispensing record. Audit records contain no reason/allergy
  text. The attachment named WarningOverridePopup, but that class was absent;
  AllergyConfirmPopup was enhanced instead, without creating a dialog class.
- Save still uses one transactional combined consultation workflow. A failed
  second medicine leaves both inventory and visit count unchanged. The internal
  ConsultationWorkflow carries the reason without changing ClinicSystem API.
- Inventory labels zero usable stock as “Out of stock”. Cross-batch depletion
  remains FEFO, rejects another dispense at zero, creates no transaction on that
  failure, and updates low-stock alerts. Medication history and reports contain
  the saved consultation administrations.
